0基础用Vibe Coding创建个人网站全记录

发表于2026-05-16|更新于2026-05-16|技术

“注：本文大部分由ai撰写，仅作技术分享使用，文章的ai味儿不代表作者态度，请读者自行甄别。”

什么是 Vibe Coding

Vibe Coding 不是写代码，是描述你想要的东西，AI 帮你实现。不需要懂编程语言，但需要能说清楚”我想要什么”——剩下的交给 AI。

本文记录用 Hexo + Butterfly 主题搭建个人博客的全过程，从零到上线。

一、开始之前：先选工具链

开始之前，先搞清楚几个东西分别是什么、怎么装。

VS Code

整个建站过程首先需要一个开发环境，我用 VS Code。

VS Code（Visual Studio Code）是微软出的免费代码编辑器，应该是目前最流行的编辑器之一。去 https://code.visualstudio.com 下载安装即可，一路点下一步，不需要任何特殊配置。装好之后打开是一个窗口，左边是文件列表，右边是编辑区。

Claude Code

Claude Code 是 Anthropic 公司出的终端原生 AI Agent。它跟 ChatGPT 的区别在于：ChatGPT 只能对话，Claude Code 能直接读写你的文件、执行终端命令、一条龙地完成”创建项目 → 装依赖 → 改配置 → 部署上线”这种完整任务。直接在vs code的扩展商店里搜索Claude即可。

也可以安装命令行版本，打开 VS Code 的终端，输入：

一行命令，装完就能用了。之后在终端输入 claude 启动，或在 VS Code 里呼出它的对话面板，直接打字提需求。

Claude Code 的默认模型是 Claude Sonnet（付费 API），需要绑定 Anthropic 账号和 API Key。

cc-switch

如果你不想只用 Anthropic 的付费 API，有一个叫 cc-switch 的小工具可以一键切换 Claude Code 背后调用的模型。比如你搞到了更便宜的 DeepSeek API Key，用 cc-switch 切过去，Claude Code 的工作方式不变，但背后干活的是 DeepSeek 模型。对于预算有限的个人用户很实用。

DeepSeek

DeepSeek 是目前api性价比最高的模型。去 platform.deepseek.com 注册账号，在”API Keys”页面创建一个 Key，复制下来。然后配合 cc-switch 填入 Claude Code，或者填进 Cursor 等工具里，就能用。

其他免费选项

  • Cursor：一款独立的 AI 编程编辑器（基于 VS Code 改造），每月有免费 API 额度，适合不想折腾 API Key 的用户。
  • Trae：字节跳动出的 AI Agent 应用，也有免费额度，国内网络友好。

这些工具原理都一样——你把需求说清楚，它帮你改文件、跑命令。

静态网站生成器是什么

简单说，你写 Markdown，它帮你生成一整个 HTML 网站。类比一下：你在 Word 里写文档，点一下”导出为网页”，整个排版、导航、样式都自动搞定。Hexo 就是这个”导出”工具，Butterfly 是其中一套很漂亮的排版模板。

选 Hexo + Butterfly 主要因为：Node.js 生态一条龙（装东西全靠 npm）、中文社区活跃文档不愁、Butterfly 主题功能全（暗黑模式、搜索、评论、代码高亮都是现成的）。

二、环境这关怎么过

很多人卡在环境配置上。其实用 Vibe Coding 的方式，你根本不需要手动装任何东西。

直接对 AI 说一句话就够了：

“帮我用 Hexo 和 Butterfly 做个个人网站”

AI 会自动检测你电脑上有没有 Node.js——没有就让你装，或者直接给你命令。Node.js 可以理解为”运行 JavaScript 的环境”，npm 是”全世界的代码库，免费拿来用”。这两句差不多就是你需要知道的全部背景知识了。

过程中 AI 会在命令行里跑很多命令，比如 npm install 会刷一屏幕的进度条。不用担心，它只是在下东西。命令行和 Windows 的图形界面本质上是同一台电脑的两种操作方式——一个靠鼠标点点点，一个靠键盘敲字。用 Vibe Coding 的话，敲字的事都交给 AI，你看它跑就行。

如果中途红了、报错了、卡住了——把那段红色的报错信息原样复制，丢回给 AI。绝大多数时候它能自己看懂并修复，如果不行就换个ai。这也是 Vibe Coding 的核心循环：你说需求 → AI 动手 → 出错 → 把错丢回去 → 修好继续。

改这个网站，主要改的其实就两个文件：

_config.yml 管网站本身——标题叫什么、作者是谁、网址是多少、语言是什么、部署到哪里。它是网站的身份证。

_config.butterfly.yml 管网站外观——导航栏放哪些菜单、侧边栏要不要、搜索开不开、评论用哪个、暗黑模式要不要。它像一个开关面板，你想开什么功能，就在里面找到对应的选项，把 false 改 true。

其他的文件你不用手动去碰。想改什么东西的时候，直接问 AI 就行：”帮我把导航栏改成中文””帮我加个本地搜索””帮我把头像旋转效果关掉”。它知道该在哪个文件改哪个参数。

主题配置是怎么工作的

Butterfly 主题自己带了一套默认配置（在 node_modules/hexo-theme-butterfly/_config.yml 里），你不要去改它。你在项目根目录写的 _config.butterfly.yml，相当于只覆盖你想改的部分。好比默认是蓝色的墙，你告诉 AI “帮我把墙刷成白色”，它只动墙的颜色，其他不动。

这个设计很关键——意味着你不需要从零开始填几百行配置，你只需要写你关心的那几项。

浏览器打开 http://localhost:4000，看到的就是最终上线后的样子。改配置、改文章之后也可以先本地看看再部署，出错了不丢人。端口占用了换个数字就行，比如 npx hexo server -p 4005。

GitHub Pages 部署

GitHub Pages 是 GitHub 提供的免费静态网页托管服务。你把 HTML 文件放在仓库里，它就自动给你一个公网网址。

拿它和传统的买服务器建站比一下：

GitHub Pages 买服务器（VPS/云服务器）
费用 免费 每月几十到几百不等
维护 零维护，GitHub 帮你管 需要自己装系统、配环境、打补丁
速度 CDN 全球加速 看机房位置和带宽
适合什么 静态网站（博客、文档站、作品集） 动态网站（需要数据库、用户登录等）
上线流程 推代码 → 自动部署 SSH 登录 → 装 Nginx → 上传文件 → 配域名 → 配 SSL

对于一个个人博客，GitHub Pages 完全够用了。它唯一的限制是只能托管静态文件——HTML、CSS、JS、图片——不能跑 PHP、Python 之类的后端程序。但 Hexo 生成的恰好就是纯静态网站，所以完美匹配。

传统服务器建站是怎样的（简短对比）

如果你买一台云服务器，比如阿里云或腾讯云最低配的 ECS，典型的建站流程大概是：

  1. SSH 登录服务器，装 Nginx：apt install nginx
  2. 把本地生成的 HTML 上传到服务器：scp -r public/* user@服务器IP:/var/www/html/
  3. 配置 Nginx 的站点文件，指定域名和根目录
  4. 去域名服务商配置 DNS，把域名 A 记录指向服务器 IP
  5. 用 Let’s Encrypt 申请免费 SSL 证书，配置 HTTPS
  6. 设置 Nginx 开机自启、定时更新证书

这还只是最简版本。实际你还得操心服务器安全（改 SSH 端口、配防火墙、禁止 root 登录）、监控资源占用、处理流量峰值。个人博客这种场景，为这些事花时间不太划算。GitHub Pages 把这些全免了。

加评论系统

评论我选的是 Giscus。它本质上是把 GitHub Discussions 当成评论数据库——读者在文章下面留言，内容实际存在仓库的 Discussions 里。好处是完全免费、没有广告、不需要自己搭后端。

配置步骤：

  1. 打开 giscus.app，填你的仓库名
  2. 页面自动生成一段配置，里面有 data-repo-id 和 data-category-id
  3. 把这两串 ID 复制给 AI，说”帮我填进 Giscus 配置”

最后

这次建站，从头到尾我没写过一行 HTML 或 CSS。每一次改动都是”帮我把 XXX 改成 YYY”、”为什么 XXX 一直转圈”、”怎么加搜索”——描述问题，AI 动手。这就是 Vibe Coding 的核心：你把精力花在”想要什么”上，而不是”怎么写出来”上。

网站上线只是第一步。后面慢慢加文章、改样式、加新功能，每一次都是一次小的 Vibe Coding 循环。
